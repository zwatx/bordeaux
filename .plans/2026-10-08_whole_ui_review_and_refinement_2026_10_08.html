Bordeaux whole-UI design review (read-only)

I made no edits and ran no GUI, Bash or builds. I opened all 31 screenshots myself and checked findings against the actual CSS cascade and component source.

1. Diagnosis and direction

Why it feels basic. No single screen is badly broken, and the field-first layout is right. The "unfinished" feeling has four causes:

  1. There is no design system underneath; there is a stack of passes.
  • About 20 distinct font sizes (8–23px) across 282 hard-coded font-size declarations, plus font: shorthands.
  • 151 hard-coded border radii (3–14px).
  • About 20 separate button classes.
  • 60 !important in app.css. Its top "polish" layer (app.css:1–182) overrides base rules (:264+), and later files then undo the polish layer per surface.
  • The push dialogs use their own hard-coded navy palette (robot-push.css, 47 hex/rgba values).
  • Each surface was tuned on its own, so nothing quite matches anything else.
  1. Hierarchy has flattened.
  • --txt-2 #c2c7cf and --txt-3 #aeb5bf are nearly the same, so secondary and tertiary text don't separate.
  • A selected segment is --bg-4 on --bg-2, roughly a 1.2:1 surface difference, so it barely shows.
  • A disabled library button only changes to --txt-3, which is the same colour as ordinary metadata.
  1. Selection and emphasis rules are inconsistent. Selection is shown five different ways:
  • Accent border plus soft fill: Settings shapes and drivetrain cards, optimizer rows.
  • Neutral --bg-3: library and outline rows.
  • --txt-3 border: routine cards.
  • Raised neutral: segmented controls.
  • Grey underline: library tabs.

Blue mostly decorates icons instead of meaning "current" or "primary".

  1. Every action is always visible, and some system details leak through.
  • Always visible: … on every library row, a trash icon on every outline row, ↑↓🗑 on every routine card, and boxed + insert chips.
  • Leaks: raw IPC error prefixes, a global summary::after{content:'Show'}, an unstyled className:'btn', and uppercase tracked labels outside the inspector.

Direction: "precise graphite instrument". Keep the identity and make it consistent.

  • Keep:
  • Space Grotesk for UI text and JetBrains Mono for numbers.
  • The graphite ladder (--bg…--bg-4) and the blue accent (--accent #7ea2ed, --accent-surface #3f6fd0).
  • The HUD constraint bar, the tool rail with key hints, the docked timeline with feature lanes, the inspector header icon tile, the choice-browser card, the Settings footprint preview with vertex editor, the optimizer comparison rows ("In use"), and the explicit push scope copy.
  • One meaning for accent:
  • The current object or selection in lists and cards (soft fill plus a 2px accent bar or accent-line border), focus rings, and the single primary commit per surface.
  • Hover stays neutral.
  • The chosen option in a segmented control is a clearly raised neutral.
  • Tokens to introduce:
  • Type scale: 10.5 / 11.5 / 12.5 / 14 / 17.
  • Radii: 4 / 6 / 10.
  • Heights: inputs 34px, buttons 32px, compact 28px.
  • Text: --txt-3 ≈ #8f96a0 (about 6:1 on --bg-1, about 5.6:1 on --bg-3; verify) and a separate disabled treatment.
  • Remove all sub-10px UI text: 37 declarations at 8–9.5px.
  • Mono only where alignment or character comparison matters: editable numbers, timecode, coordinates, host keys, filenames. Everything else uses tabular sans.
  • Three button tiers: primary, secondary and quiet (with a quiet-danger variant).
  • Labels: sentence case, 11.5–12px, weight 500, --txt-2, no letter-spacing.

Primary tasks this must serve: authoring a path (canvas → outline → inspector), timing review (timeline, constraints), routine building (flow → branch → inspector), robot profile (Settings), optimization, and the explicit local Save versus scoped Push boundary.

Budget constraint that shapes the plan:

  • CSS is 139,962 / 143,360 bytes, about 3.4 KB of headroom.
  • JS is 540,090 / 540,672 bytes, only 582 bytes of headroom.
  • About 9 KB+ of CSS is dead: .pathlib-* (app.css:865–910, 939–940, and touch rules), .exportbtn, .pathsw*, .planner-family, .stat3, .range-disclosure, .cmd-project-head/foot/icon/iconbtn. Deleting it, and folding the polish layer into the base rules, pays for the new work.
  • Batches must be CSS-first. JSX changes must be net-neutral; class swaps and copy changes roughly are.
  • If a batch genuinely needs JS bytes, bring the measured delta to root rather than raising the cap.
